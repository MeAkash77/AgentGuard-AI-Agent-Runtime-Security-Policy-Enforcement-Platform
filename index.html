Runtime security layer for autonomous AI

See what an AI agent actually does. Stop unsafe actions before they land.

Adrian monitors an agent's actions, tool calls, outputs and reasoning context at runtime. It evaluates each step against the agent's authorised remit and can allow, alert, hold for human review, or block.

01 / The problem

AI agents can act. Traditional monitoring mostly watches logs.

Adrian adds a runtime control layer that looks at the agent's behaviour and the context behind an action, so security decisions happen while the session is still alive.

◎

Observe

Capture agent activity such as tool calls, actions, outputs and session context through the SDK and runtime connection.

◈

Understand

Correlate what the agent is doing with its defined remit and reasoning context instead of relying only on a static list of known attacks.

◇

Control

Turn a classification into an operational response: continue safely, create an alert, request human review, or block the action.

04 / Detection model

From benign activity to maximum-severity escalation.

The repository's MAD taxonomy includes benign M0, medium-confidence misuse M2, high-risk misuse M3 and maximum-severity M4 categories.

05 / For a recruiter

This is more than a landing page. It is a systems project.

The repository demonstrates backend engineering, security policy design, AI/LLM integration, SDK design, real-time communication, data persistence and a production-style dashboard.

What the project demonstrates

  • Go backend with API, WebSocket and persistence layers
  • Python and TypeScript SDK integrations
  • Runtime event ingestion and classification pipeline
  • Policy/remit-aware safety decisions
  • Agent session and audit visibility
  • Docker-based self-hosted deployment path
